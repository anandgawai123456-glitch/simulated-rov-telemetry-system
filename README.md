# Simulated ROV Telemetry Monitoring System

Coratia Technologies engineering assessment implementation. This is a simulation-only desktop application; it does not connect to or control a real ROV or flight controller.

## Architecture

- `simulator/telemetry_generator.py`: creates deterministic, plausible JSON telemetry and supports fault injection.
- `telemetry/parser.py`: parses JSON and reports malformed input without crashing.
- `telemetry/validator.py`: validates required fields, types, physical bounds, and configurable warning thresholds.
- `telemetry/state.py`: maintains the latest valid sample and tracks `VALID`, `STALE`, `INVALID`, and `UNAVAILABLE` quality.
- `telemetry/processor.py`: UI-independent processing pipeline.
- `app_backend.py`: Qt bridge, timer-driven simulator, timestamped event log.
- `dashboard/Main.qml`: Qt Quick dashboard. Validation logic remains in Python.
- `tests/`: automated tests.
- `docs/mavlink_integration.md`: proposed read-only ArduPilot SITL integration.

## Requirements

- Python 3.10+
- PySide6 (Qt Quick / QML)
- pytest (tests only)

## Install

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

On Ubuntu, if Qt cannot initialize due to missing system libraries, install the standard Qt/XCB runtime dependencies for your distribution. Run from a graphical desktop session.

## Run

```bash
source .venv/bin/activate
python main.py
```

Press **Start stream** to begin simulated telemetry. **Stop stream** stops incoming records; after the freshness timeout, the quality changes to `STALE`.

Use the fault selector to inject malformed JSON, a missing field, low battery, an out-of-range sensor, heartbeat loss, or a stopped stream. Select **No fault** or press **Clear fault** to resume normal records.

Event transitions and warnings are appended to `logs/events.log` in UTC.

## Thresholds and assumptions

Defaults are in `config/thresholds.json` and mirrored in `telemetry/validator.py`:

| Parameter | Default | Meaning |
|---|---:|---|
| Battery warning | 21.0 V | Warning below this voltage |
| Battery critical | 19.0 V | Critical warning below this voltage |
| Depth valid range | 0–100 m | Values outside are rejected |
| Attitude warning | ±45° | Warning when absolute roll/pitch/yaw exceeds this |
| Attitude valid range | ±180° | Values outside are rejected |
| Freshness timeout | 3.0 s | Last valid sample older than this is stale |

Assumptions: battery voltage is pack voltage in volts; depth is positive downward in metres; attitude values are degrees; heartbeat is a boolean; timestamps are ISO 8601.

A syntactically valid but semantically invalid record does not replace the last valid sample. The quality indicator communicates whether that retained sample is current.

The current code uses the defaults in `DEFAULT_CONFIG`; the JSON file documents the same settings for easy review and future configuration loading.

## Future Implementation

The current project provides a simulation-based foundation for ROV telemetry monitoring. The following features are planned extensions to improve monitoring, diagnostics, and real-time vehicle visualization.

### 1. Electrical Telemetry and Power Monitoring

- Real-time battery voltage and current monitoring.
- Live power consumption calculation and visualization in watts.
- Historical graphs for voltage, current, and power consumption.
- Battery percentage estimation and remaining runtime prediction.
- Configurable electrical warning and critical thresholds.
- Detection and visualization of abnormal voltage drops and power fluctuations.

### 2. Real-Time ROV Visualization

- Interactive 2D and 3D ROV visualization.
- Live vehicle orientation using roll, pitch, and yaw.
- Real-time depth and heading indicators.
- Thruster status and output visualization.
- Sensor health and communication status indicators.
- Visual representation of vehicle movement and operating conditions.

### 3. Live Telemetry Integration

- Read-only integration with ArduPilot SITL through MAVLink.
- Support for real-time telemetry streams from compatible ROV systems.
- Improved telemetry logging and historical data playback.
- Configurable alerts for communication loss, battery conditions, and sensor faults.

### 4. Advanced Monitoring and Diagnostics

- Historical telemetry dashboards with selectable time ranges.
- Fault history and event timeline.
- Telemetry recording and playback for debugging.
- Data export for engineering analysis.
- Improved system health monitoring and diagnostics.

These are planned enhancements and are not implemented in the current assessment prototype. Real hardware integration will require compatible vehicle interfaces, validated sensor data, and hardware-specific calibration.

## Third-party resources and limitations

- PySide6 / Qt for Python provides the desktop runtime and QML bridge.
- pytest provides automated tests.
- Telemetry values are generated by the project-owned simulator; no real vehicle data or external sample dataset is used.
- This is an assessment prototype, not a certified ROV safety system. Thresholds are illustrative and must be calibrated for a real vehicle. Depth-message availability and pressure-to-depth conversion depend on firmware and sensor configuration.
